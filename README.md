iRAS 是一个面向**水产养殖工程师、设计院、高校研究者**的循环水养殖系统(Recirculating Aquaculture System)工程设计开源工具。覆盖**工艺设计 → 碳酸盐平衡水化学 → P&ID 工艺图 → 设备清单 → 投资财务评价 → 16 章可研报告生成**的完整工作流。

## 质量保证

每个版本发布前都要通过一整套自动化门禁:页面内自检、13 条数值基线逐位比对、
跨文档版本口径、文档默认值与代码的一致性、上下游数据契约、手册正文数字与代码符号的
比对,以及手册表格与案例章**直接从源码/真实模型生成**(值由代码出、释义由人给,不手抄)。

其中**页面内自检随产品发布**——在任意 iRAS 页面地址后加 `?selftest=1` 即可运行,
当前 **43 项**全绿(徽章与实测由门禁锁定,不一致即转红)。
其余门禁是开发期工具链,不在发布包内。

**每条门禁上线前都跑过负对照**——没跑过负对照的校验器与没有校验器等价
(本项目已多次遇到「断言写好但全绿」:判据宿主填错、锚定工况走不到、告警写了没人查)。

⚠ 三条反复验证过的经验:

- **审计器把被审对象跑瘸了,得到的"干净"是假的;把自己跑瘸了,得到的"红"也是假的。**
  下游审计两轮内此类问题出现 7 次(缺依赖、共享 storage、转义丢失、深度截断……),
  全部由负对照或假红暴露,读代码读不出来。出现"全绿"或"全红"这类整齐结果时,先怀疑量具。
- **判据要作用在"生效的东西"上**:注释里提到的 id 不是 id,历史叙述里的旧默认值不是当前值,
  运行时"读过"不等于"在用"。分不清这三者,校验器就会满屏假红或一片假绿。
- **判据错比代码错更贵**——它会让人去改对的东西。曾有两次:一次把合规的设计判成红,
  差点逼出错误的"修复";一次是登记表式判据**漏登记**,于是手册版本号停在两个版本前
  而门禁全绿。**登记表式判据的强度完全取决于表的完整性。**

## 主要功能

**工艺设计**
- 分阶段养殖工艺链：鱼池 → 微滤 → 蛋分 → 生物滤池 → 脱气 → 增氧 → 消毒 → 反硝化，逐节点沿程水质求解
- 负荷模型：TAN / TSS / 溶解性 COD / 耗氧 / CO₂ 按投饵量与蛋白率推导，区分日均与小时峰值
- 生物滤池按**面速率**选型（载体面积 → 单程去除率 → 稳态 TAN），区分面积侧受限与水力侧受限
- 碳酸盐平衡求解：pH / NH₃ 物种 / 缓冲强度 β / 方解石饱和度 Ω，平衡常数对照 PyCO2SYS 验证
- 增氧双路径：纯氧（氧锥 mainline / bypass）与空气曝气，含 TGP 总溶解气体压力核算
- 完整热平衡：水侧（代谢 / 设备 / 补水 / 蒸发 / 除湿 / 气液接触器）+ 车间侧（围护 / 通风 / 室内产热），含自然冷却判据

**工程输出**
- **P&ID 工艺图**自动生成（`pid.html`，符合 ISA-5.1，可导出 PNG/SVG）
- **设备清单**（`equipment.html`，每台规格 + 数量 + 单价，设计院投资概算可直接引用）
- **投资财务评价**（`finance.html`，NPV / IRR / 回收期 / 盈亏平衡 + 8 张标准财务表 + 5 因子敏感性 + Excel 导出）
- **16 章可行性研究报告**（`report.html`，按发改委 2017 编制规范输出 .docx）

**工程化**
- 8 种主流鱼种参数库（三文鱼 / 大菱鲆 / 石斑 / 罗非 / 加州鲈 / 鳗鲡 / 鳜鱼 / 对虾），支持跨盐度阶段
- 多模块并联 + N+1 备用；站级设备（液氧储罐等）独立管理
- 全场气候库与鱼种默认气候联动；方案自动保存与 JSON 导入导出
- 108 项工艺参数全部可调，每项带范围钳制、物理含义与「何时调」建议（见技术手册附录 G）

## 自检 (Self-test) 🔧 面向二次开发者

**普通用户日常使用无需理会本节。** 直接打开 `index.html` 填参数即可。

唯一可能用到的场合是**怀疑软件算错了**：访问 `index.html?selftest=1`，
它会跑 14 个固定工况与内置基线比对并弹出结果面板。

- **全 PASS** → 计算内核完好，问题在输入参数或对结果的理解
- **有 FAIL** → 这份文件被改动过或已损坏，别用它出报告

改过模型或做二次开发的人，请改完立刻跑一次；命令行版本：

```bash
npm install && npm test        # 九项，任一失败非零退出
```

完整说明（受检字段、不变量断言、容差、突变测试验收办法）见 [`tests/README.md`](tests/README.md)
与技术手册「版本演进说明 → v1.9.2 → v1.9.3 → C 节」。

**为什么需要它**：一次审计发现，此前对外发布的四工况基线是用一份**外部测试脚本**跑出来的，
而该脚本写于成本模型扩展之前，调 `calcCostEstimate` 时少传三个参数——它算的是旧口径，
误差 3.41 元/kg，被写进三个文件对外发布。根因不是某个公式错，
而是**验证路径与产品路径不是同一条**。因此本自检的唯一设计约束是：
必须调用真实的 `recomputeAll()`、读真实的 `lastResults.summary`，不得重新实现任何计算管线。

## 使用场景

iRAS 适用于以下场景:

- ✅ **设计院**:RAS 项目的早期工艺方案 / 概算 / 可研草稿
- ✅ **业主 / 投资方**:RAS 项目可行性快速评估
- ✅ **设备商 / 总包**:项目选型与方案对比
- ✅ **高校 / 研究者**:RAS 工程教学与课程设计 (碳酸模块对接 PyCO2SYS 实验室标准)
- ✅ **政府机构**:RAS 产业园规划与项目评审

iRAS **不适合**的场景:

- ❌ 替代正式的环境影响评价 / 安全评价 / 节能评价(必须由有资质机构出具)
- ❌ 替代施工图详细设计(本工具是工程概算阶段,精度 ±40%)
- ❌ 替代专业财务软件做 Monte Carlo 模拟(本工具是单点确定性现金流模型)

## 免责声明

本工具计算结果仅供工程概算参考。

> **关于成本口径**:分两层输出 —— **工艺运行成本**(饲料 + 工艺电耗 + 工艺消耗品 + 维护 + 保险 + 补水 + 排污 + 折旧)与**企业全成本**(再加苗种 + 人工 + 管理费)。两者**均不含**包装/物流/加工、疫苗药物、顾问技术服务费,这三类随项目差异极大须另行估算。
>
> **关于工艺参数**:生物滤池动力学、各类去除率与安全系数为**通用工程取值**,用于方案比选与量级估算。这类参数随填料型号、运行浓度、菌群状态、设备厂家差异很大,不同来源实测值可相差数倍。**具体项目应以设备厂家实测数据或设计单位参数覆盖默认值,不应直接作为施工图依据。**

- 实际工程必须结合现场水质监测、批量试验数据、当地规范与专业工程师判断
- 投资概算精度约 ±40%,实际造价以厂商报价和工程招标为准
- 不替代正式的环境影响评价 / 安全评价 / 节能评价
- 氧锥拓扑 mainline / bypass 经济性对比基于 1000 t 大西洋三文鱼工况实测,中小项目(Q &lt; 5000 m³/h)bypass 优势减弱,建议项目具体核算
- "系统排水"输出口径为**沉淀池入口**浓度(含污泥,质量守恒),不可直接对照 GB 8978 等污水管口标准
