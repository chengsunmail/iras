### v2.0.0:热平衡架构重构 + 气液接触器 + 规范对标 ⭐ 最新

自 v1.2 引入双节点热平衡以来**最大的一次模型改动**。热平衡代码**净减少 65 行**；
13 条数值基线全部重算；自检 14 → **16 项**。

#### 车间温度：从因变量改为输入

v1.2–v1.9.3 把 `T_room` 作为空气节点能量方程的**解**，自由漂浮、无任何调节系统。
后果：热带鱼种算出车间 **9–14 °C / RH 99%**。

而实测与规范一致指向「空气 ≥ 水温」：

| 来源 | 车间气温 | 水温 |
|---|---|---|
| 摩洛哥 Amghass 站实测（AQUAIR 数据集 84 天） | 16.0 均值 | 鳟鱼 12–16 |
| 大连河豚车间 CFD + 实测 | 22–23 | 17 |
| ASHRAE HVAC Applications Ch.6 / CJJ 122-2017 | 水温 +1~2 °C，RH 50–70% | — |
| **v1.x 本工具（热带鱼种）** | **9–14** | **25–30** |

**方向反了 15–20 K。** v2.0 改为 `T_room = T_水温`（暖通维持），`roomRH_set` 默认 65% 可调。
由此删除 Picard 迭代、闭式解、钳位与「钳位时静默丢弃能量」缺陷；池面显热 `Q_pool_loss ≡ 0`。

> 由此消失的长期争议：水面传热系数取 5 还是 15、太阳辐射要不要建模、钳位缺口去哪
> —— 温差为零后**全部无关**。

#### 气液接触器 —— 本版核心新增

v1.x 中脱气塔与 MBBR 曝气的气水直接接触量 **96,287 m³/h**（机械新风的 **4.2 倍**）
**完全不在热平衡账内**。

出口按**水温下饱和**计算，**无需标定系数**，两个独立领域实测支撑：

- Karimi 等 2020（Wageningen，8 组 GLR）：出口 RH 实测 **98–100%**，与进水温差平均 0.77 °C
- Talati & Stenstrom 1990（ASCE）：鼓风曝气 hf = 1，尾气实测现场研究确认

**Δh 可为负** —— 湿热空气遇冷水在填料上结露放热：

| 三文鱼 1000 t 年均 | 接触器净排热 kWh/d | 比电耗 |
|---|---|---|
| Bergen | +16,405 | 10.46 |
| 青岛 | +9,460 | 11.54 |
| 上海 | +1,123 | 12.45 |
| Doha | −11,527 | 15.37 |
| **三亚** | **−18,470** | **15.96** |
| 三亚（设计夏） | **−53,482** | 24.73 |

**脱气塔在热带是凝结加热器而非冷却塔。** 这是 Atlantic Sapphire（佛州 Homestead）、
宁波象山 Nordic Aqua 一类项目的核心成本，行业内普遍未量化。

#### 自然冷却与接触器：抢同一个资源，不叠加

v2.0 接入接触器后，**自然冷却在冷天基本失效** —— 而那正是它原本最有价值的场景。
两者用的是**同一个物理资源：室外冷空气**，而**接触器是必开的**（脱 CO₂ 是刚需）。

| 工况（三文鱼 1000 t 青岛） | 水侧方向 | FC 贡献 g | FC 开→关 比电耗 |
|---|---|---|---|
| 设计冬 | **heat** | 0.00 | 12.57 → 12.57，**Δ 0** |
| 年均 | cool | 0.13 | 11.54 → 11.59，Δ 0.049 |
| 设计夏 | cool | 0.00（室外 32 °C 过热） | Δ 0 |

> **⚠ v1.9.2 的自然冷却效益结论已订正。** 「寒冷气候热泵费 1.68 → 0.29 元/kg」
> 是在**接触器缺失**时算出的 —— 那部分「省下的电」其实早已被脱气塔省掉，**两者不叠加**。

UI 保留开关：年均仍有 13% 贡献（年均才是能耗口径）、可作对照基准、
且真实工程可冬季降 G:L 把负荷让给自然冷却（模型暂未建）。

新增 `fcUnavailReason` 区分四种不可用：`off` / **`not_cool`（水侧需制热，v2.0 主因）**
/ `uneconomic` / `no_dt`。

#### 暖通能耗计入

三部分现已全部进电耗：水侧热泵（`thermalCostDaily`）+ 除湿机（`dehumCostDaily`，v1.9.2 即有）
+ **车间围护与通风显热（`hvacCostDaily`，本版新增）**。

`T_room = T_w` 后车间与室外温差恒为「水温 − 气温」：正 = 失热需加热，负 = 得热需制冷。
**加热与制冷 COP 不同，分别取温度修正后的 COP**，不可对绝对值统一折算。
该项在寒冷地区与水侧热泵同量级（Bergen 设计冬 3,355 vs 2,847 kWh/d）。

#### 脱气塔对标教科书

`co2StripperGtoL` **3 → 5**，新增 `co2PackingHeight_m` **1.5 m**。
依据 Timmons Ch.10 p.244–245：CO₂ 汽提 G/L 为 **5:1–20:1**（常规曝气才 <3:1，
增氧 0.003:1–0.05:1，三个用途差三个数量级）；填料高度限于 1.0–1.5 m。
Karimi 2020 实测 GLR > 5 无额外增益、Summerfelt 2003 最优 5.1 —— **四个来源一致**。

比功率 3.47 → **5.79 kW/1000 m³/h**，进入 Summerfelt 2009 的 5–15 区间，
顺带解决 v1.9.2 审计 P4 遗留。

> **风压保持 2.5 kPa。** 原注释建议上调至 4.3–8.0 kPa 是把**曝气风机档位误套到脱气塔**
> —— 曝气克服静水压（约 10 kPa/m 水柱），脱气只克服填料流动阻力
> （化工准则 0.2–0.4 kPa/m，液泛点才 1.3 kPa/m）。

#### 鱼种参数库水质自洽性修正

新增 `t17` 断言发现**三处参数组合物理不可行**。共同点：`density` 或耗氧系数在某版本被调高，
而 `turnover` 未同步 —— **每次改动单独看都对，组合起来把参数推到物理不可行区**：

| 鱼种/阶段 | 原状态 | turnover |
|---|---|---|
| 鳗鲡 养成期 | **出池 DO = 0.00 mg/L**（完全耗尽），CO₂ 超阈值 44% | 2.5 → 5.0 |
| 鳗鲡 黑仔期 | 出池 DO 0.69（阈值 5.09） | 3.0 → 4.5 |
| 罗非 苗种期 | 出池 DO 3.20（阈值 4.70） | 6.0 → 8.0 |
| 大菱鲆 中鱼期 | 池内 CO₂ 15.2（阈值 15） | 2.5 → 3.0 |

以鳗鲡为例：v1.9.2 把养成期密度由 40 上调至 120 kg/m³（修正 CAPEX 失真），
同版新增 TSS 附加耗氧项 —— 高密度下该项占总耗氧 **67%**，两者叠加使出池溶氧归零。

> **golden-master 基线对此无能为力** —— 它们从未 FAIL 过，因为基线记录的正是错误状态本身。
> 这类缺陷需要**面向工程约束**的断言。

#### 已知限制

**① 接触器蒸发未计入水量平衡。** 热量已完整计入（Δh 含潜热，t16 验证潜热占 86%），
但水的**质量**尚未进入 `V_makeup`。实测三文鱼青岛设计冬：接触器蒸发
**584.6 kg/h（14.03 m³/d）**，是池面蒸发 19.8 kg/h 的 **29.5 倍**，占补水量 **6.0%**。
补水量、补水加热、补水费与排污量均系统性低估约 6%。**属单向偏差，列入 v2.1。**

**② 凝结水对盐度的影响未建模。** 湿热气候 Δh 为负时净产水，三亚设计夏约 **33 t/d**。
淡水场是白得的补水；**海水场会被持续稀释**，影响换水策略与盐度控制。

**③ 暖通侧未含太阳辐射与人员负荷。** 围护体系本身完整（U 值四项可调 + 4 档保温预设
+ 通风热回收 + 地板对地温单独算），但太阳辐射与采光带得热未建模 ——
大连 RAS 车间 CFD+实测显示屋顶采光带可把墙温推到 29 °C（同期水温 17 °C），
故**高日照、设采光带的车间夏季制冷负荷偏保守**。

其它遗留：`contactorRecovery` 默认 0；MBBR 流化下限与 `bfTankDepth` 参数缺失；
石斑三阶段 DO 余量仅 +2%/+3%/+10%；蛋分有支路泵而无供气动力项；
单池面积 DB 21/T 2350 规定 5–30 m²，本工具每阶段一个池、池数由用户设置。

### v1.9.1:液氧口径修正 + 蒸发系数量纲修正

与英文版 v2.0 同步的两处物理/口径修正。**不改变设备选型结果**,仅修正消耗品采购量与蒸发潜热。

- **液氧消耗口径修正** — 旧版用含选型余量的 `o2Demand`(含 `peakFactor` × `sAerator`)计算液氧 OPEX 与基准值。液氧是**按量计费的消耗品**,只有吸收效率应放大采购量,容量系数不应参与。新增并行口径 `o2ConsumptionDaily` / `o2ConsumptionDailyAvg`,`o2Demand` 原样保留给设备选型
  - 液氧成本:**高估 65% → 修正**(旧/新 = 1.5 × 1.10 = 1.65)
  - 鲑鱼成鱼液氧基准值:0.44 → **0.266** kg O₂/kg 饲料(文献 0.25–0.30)
  - 液氧年耗(1000 t/yr, FCR 1.2):527 t → **319 t**
  - 液氧储罐(7 天储备):10.1 t → **6.1 t**
  - 验收区间由 0.25–0.95 收紧为 **0.20–0.45**(旧区间是为迁就被膨胀数值而放宽的)
- **蒸发系数 β 量纲修正** — 旧版注释声称 β 取自 ASHRAE Applications Ch.6 的 0.045–0.075 m/s,**这是错误出处**。ASHRAE / Carrier 的池面蒸发系数是定义在**蒸气压差**上的英制系数 [lb/(h·ft²·inHg)],不能直接当作 ΔW × ρ_air 形式的 β [m/s] 使用,否则高估约一个数量级
  - 改用 Lewis 传热传质类比导出:`β = h_c / (ρ·c_p·Le^(2/3))`,β ≈ **0.0035–0.010 m/s**(旧 0.045–0.15)
  - 交叉验证:把 ASHRAE 的 0.089 换算到湿度比基准,同样得到 β ≈ 0.005 m/s
  - 实测效果:蒸发率降 2–2.4 倍(非 13 倍,因 `W_room` 自洽求解存在自补偿);**车间湿度饱和 (RH=99%) 告警消失**

> **回归验证**:`o2PeakSupplyKgH` 与 `o2Demand` 计算式**逐字未变** — 本次改的是"买多少氧",不是"配多大设备",氧锥流量与设备规格与 v1.9 完全一致。

依据详见 `VALIDATION.md` §2(蒸发系数)与 §3(液氧口径)。

### v1.9.2 (第一批):通风量口径修正 + 机械除湿机

热平衡模型的通风量口径修正,并新增机械除湿机建模。**不改变设备选型逻辑**。

- **通风量口径修正** — 旧版通风量 = `ACH × 车间体积`,而车间面积由 `1.6 × 水面积` 自动估算、水面积 = 水体/池深。结果:**养殖密度降低 → 水体↑ → 车间↑ → 通风↑ → 湿热气候下凝结放热↑ → 制冷装机暴涨**,但鱼的数量没变,新风需求本不该变
  - 新口径:`新风量 = max(ACH × 车间体积, 鱼载荷 CO₂ 稀释需求)`
  - CO₂ 需求依据文献 500 g CO₂/kg 饲料(大西洋鲑 409 Terjesen 2013 / smolt 550 Vinci 2004 / 鳗鲡 536 Heinsbroek 1990)
  - 新增可调参数:**车间 CO₂ 限值**(默认 1500 ppm)、**脱气塔尾气入室比例**(默认 0.2)
  - **ACH 默认值 1.0 有了标准依据** — 泳池馆新风标准 0.48 CFM/ft² 湿面积换算,本模型几何下约 0.9–1.5 ACH
  - **除湿不计入新风**:湿热气候通风不能除湿(室外空气比车间更湿),干冷气候靠通风除湿仅需约 0.14 ACH — 两种情况下除湿都不是通风量的决定项
- **新增机械除湿机建模** — 湿热气候养冷水鱼时通常必配(室外更湿,通风无法除湿)
  - 开启后车间湿度被控制在目标 RH,水面凝结减少 → 制冷负荷下降
  - 计算除湿量(kg/d)、除湿机电耗(kWh/d,按 SMER)、冷凝水回收(可抵扣补水)
  - 参数:开关 / 目标 RH(默认 70%)/ SMER(默认 2.5 kg·kWh⁻¹)/ 冷凝水回收
  - 海南夏工况实测:开除湿机后车间 RH 由 92% 降至 70%,凝结放热 2152 → 1222 kWh/d,除湿机电耗 1365 kWh/d,冷凝水回收 3.4 t/d

> **工程意义**:总电耗相近,但车间湿度从 92% 降到 70% — 配除湿机的真实理由不是省电,而是避免霉菌、设备腐蚀与电气故障。

### v1.9.2 (第二批):泵功率口径 + 耗氧-产热绑定 + 成本模型两层化

在第一批基础上继续修正物理口径,并把成本模型从「工艺运行成本」扩到「企业全成本」。**设备选型逻辑仍不变**(7 项 × 4 阶段回归逐位一致)。

**物理口径修正**

- **泵功率口径 —— 轴功率 vs 电功率** — `shaftKw = 9.81QH/(3600η)` 是**轴功率**,不含电机效率。旧实现 (1) 把它直接当电耗计费,漏算电机损失;(2) 用 `pumpHeatRatio = 0.85` 把 15% 轴功率送进车间空气 —— 那是把「电机效率 85%」错记在轴功率上,而电机损失根本不在这个数里
  - 新增 `motorEta`(默认 0.95),电耗 = 轴功率 / motorEta
  - `pumpHeatRatio` 0.85 → **0.97**;空气得热 = 轴功率 × (1/motorEta − pumpHeatRatio)
  - **车间得热原高估约 2.8 倍** → 导致 T_room 顶穿物理钳位、RH 被人为压低到除湿机永不触发
- **T_room 钳位不再静默截断** — 钳位触发时报出未闭合能量缺口。修正泵口径后钳位触发率由 30% 降至 8%
- **代谢产热改由耗氧导出** — 旧式 Schrama 系数 106 kJ/(d·kg^0.85) 源自**饱食投喂**实测且公式无投饵率变量,套商业投饵率高估约 3 倍(1.11 W/kg vs 维持代谢基准 0.11)。改为 `池内耗氧 × 13.6 kJ/g O₂`(Brett & Groves 1979),**11030 → 4053 kWh/d**
  - 同一代谢过程同时决定耗氧与产热,由氧热当量刚性绑定,不再各取各的文献值
- **池内耗氧新增 TSS 依赖项** — 悬浮固体上附着的异养菌在**池内**直接耗氧,同样要靠氧锥供给
  - **固体管理首次与液氧账单挂钩**:微滤机去除率 90% → 40%,池内 TSS 3.0 → 5.0,液氧年耗 **334 → 481 t (+44%)**
- **总溶解气压 (TGP) 成为模型量** — `TGP = 100 + (饱和度 − 1) × 20.95`,阈值鱼苗 110% / 其他 115%,接入 DO 告警

**默认值修正**

| 参数 | 原 | 新 | 理由 |
|---|---|---|---|
| `mainPumpHead_m` | 12 | **7** | 12 是「多级跌落」档,与工具自身提示的「重力回流 5-8」矛盾 |
| `mainPumpEta` | 68 | **75** | 大流量低扬程工况选轴流/混流泵 |
| 支路泵扬程 | 10 | **7** | 支路流量小、管路短,不应高于主泵 |
| `o2SatTarget` | 各鱼种 110-165 | **统一 165** | DO 包线体检发现 5 个阶段击穿、4 个临界 |
| 苗种期饱和度微调 | +5 | **−20** | 原方向与气泡病风险相反 —— 鱼苗最敏感却配得最高 |

比电耗 17.9 → **12.0 kWh/kg**。

**审计发现并修复的 Bug**

- 除湿机电耗未计入 OPEX —— 开除湿机反而降成本,物理上不成立
- 除湿机无 CAPEX、不进设备清单
- `dehumCondRecovery` 断链 —— 有默认值有用途,但无 UI / 无载入 / 无监听
- v1.9.2 第一批的全部新输出(除湿量/电耗/排热/等效 ACH)算了但没有界面出口
- 一处与 v1.9.1 修正自相矛盾的陈旧注释

**DO 击穿告警改为按约束诊断**

旧文案建议「提高循环倍数或 DO 目标饱和度」。统一到 165% 后,「提高饱和度」已成为**危险建议**(会撞进刚规避的气泡病风险)。改为逐条计算四条出路的当前值、所需值与卡点:降密度 / 提 turnover(>6 次/h 标注为工程上做不到)/ 提饱和度(超 TGP 阈值则标红劝阻)/ 改善固体管理。

**成本模型两层化**

```
工艺运行成本 = 饲料 + 工艺电耗 + 工艺消耗品 + 维护 + 保险 + 补水 + 排污 + 折旧
企业全成本   = 工艺运行成本 + 苗种 + 人工 + 管理费
```

新增 7 个成本项、11 个可调参数(维护费率与基数 / 保险费率 / 管理费率 / 劳动生产率 / 人均年成本 / 最小班组 / 补水淡海水单价 / 排污单价 / 苗种单价)。

**分两层输出**的理由:工艺侧每一项都能追到物理量与公式;企业侧本质是经济估算。混进一个总数会拉低整个模型的可追溯性。

> 与 Nordic Aqua(宁波象山)2025 年报对标发现,旧口径比商业实绩低约 38%,差额几乎全在「其他 OPEX」—— 缺的是维护、保险、补水、排污这批项目,不是物理算错了。详见技术手册 21.5。

### v1.9.3（P1+P2）：部分自然冷却 + 年平均年化

**主要矛盾不是「逼近温差取几 K」，而是判据「非 0 即 1」。** 旧判据一旦跨过阈值，
EER 从 3.45 跳到 20、Q 从 0 跳到全量，两个量同时跳变 —— 阈值附近出现 **5.8 倍**成本悬崖。

**P1 容量判据**

```
Q_fc      = min(K_fc · ΔT_avail, Q_load)     K_fc = Q_design / ΔT_design
EER_fc    = EER_design · min(ΔT_avail/ΔT_design, 1)
1/COP_eff = (1−g)/COP_cool + g/EER_design
```

`Q ∝ ΔT` 是**精确**的而非线性化（ε-NTU：流量固定时 ε 为常数）。
**经济截止点自动涌现且恰好连续**：截止处 `EER_fc = COP_cool`，两条路径边际成本相等，
故 E 两侧完全相等 —— **悬崖不是被磨平，是不存在了**，且无需为它引入任何参数。

参数 `freeCoolingApproach_K` → `fcDesignDT_K`，语义由「悬崖位置」变为「单独扛满设计负荷所需的温差」，
是**换热链串联损失**：空气源（板换 2–3 + 干冷器对空气 5–10）= 8–13 K；水/开式海水（钛板换）= 3–6 K；地源 5–7 K。
UI 留空即按热源自动取（空气 11 / 水·海水 4 / 地源 6）。**填错几 K 只会让曲线挪一小段。**

**P2 年平均：24 点数值积分**

阈值函数在均值处取值 ≠ 函数的均值（Jensen）—— 旧模型切设计冬判定全年可用（高估）、
切年均判定全年不可用（低估），**真值在中间而单点永远给不出**。
用现有三个温度点拟合正弦，T_air 与 T_source 各自振幅、同相位摆动，逐点跑真实热平衡再平均。

闭式解保留为诊断量：**对贡献率精确**（青岛 0.3826 vs 收敛数值 0.3826），
但**能耗偏乐观 1–7%**（未计 Q_load 与冷源温度的相关性）—— 这正是改用数值积分的原因。
点数取 24：N=12 误差 −1.24%~+1.03%，N=24 降到 0.15% 以内；成本仅 0.9 ms。

**备用设备计入设备投资**

模型一直按 **N+1** 给每个模块配备用，设备清单也展开了备用台数，但 CAPEX 是**按工艺容量**计价的——

即实际装 150% 只按 100% 计价。这是 v1.3 就存在、因从未按装机量计价而未暴露的漏算，本版一并修正（+35 万）。

另发现利用小时的解析逻辑**被复制了 4 份**。已抽出 `hpUtilHoursOf()` 唯一出口，
并新增 `t12` 三层断言，其中一层**直接读渲染出的 DOM 文本**——这一层正是原断言的盲区。

**水质告警：NH₃ 按鱼种 + Ω 方解石**

- **NH₃**：鱼种限值表早已存在（鲑 12.5 / 罗非 100 …），tooltip 也知道，**但判据写死 25 μg/L**——
  最敏感的鲑科用了 2× 宽松阈值。改为三档（超限值红 / 超半限值黄 / 其余绿）。
- **Ω 方解石饱和度**：此前**界面上完全没有显示**（已算出并进导出载荷，只是不渲染）。
  实测**海水鱼种几乎全程欠饱和**：三文鱼 0.45–0.58、大菱鲆 0.37–0.56、对虾仅苗种期达标。
  这是模型算出的真实状态——高密度 RAS 中 CO₂ 累积压低 pH。
  **Ω < 1 会持续溶蚀混凝土池体与水泥基砂浆。**

> ⚠ **蒸发计入补水（P3 第三项）经实测后决定不做**：蒸发仅占补水 **0.06%–0.32%**，
> 折算成本 < 0.001 元/kg，而改动要把 12 条基线与三份文档数字再重算一遍。
> 该结论依赖默认 `poolCover=partial` 且换水率 5%/d；敞开池面 + 干热气候时占比会显著上升。

**上述盲区已修**

比电耗与热泵电费**没有产品出口**，因此进不了 `SELFTEST_BASELINE`、无法自检，现在只是碰巧还对着。
建议下一版补 `kwhPerKg` / `hpCostPerKg` 两个字段并纳入基线。

> **年化基准的坑**：全场年耗电与年液氧按**日值 × 365** 累加（各阶段全年并行运行）。
> 按 `stageDays` 串行累加会把比电耗低估 2.3 倍（4.2 vs 9.7）。已用年液氧 471 t 作独立锚点反查确认。

> 龙头企业全年亏损 1.79 亿元同号。

## 自检 (Self-test) 🔧 面向二次开发者

**普通用户日常使用无需理会本节。** 直接打开 `index.html` 填参数即可。

唯一可能用到的场合是**怀疑软件算错了**：访问 `index.html?selftest=1`，
它会跑 14 个固定工况与内置基线比对并弹出结果面板。

- **全 PASS** → 计算内核完好，问题在输入参数或对结果的理解
- **有 FAIL** → 这份文件被改动过或已损坏，别用它出报告

改过模型或做二次开发的人，请改完立刻跑一次；命令行版本：

```bash
npm install && npm test        # 九项，任一失败非零退出
```

完整说明（受检字段、不变量断言、容差、突变测试验收办法）见 [`tests/README.md`](tests/README.md)
与技术手册「版本演进说明 → v1.9.2 → v1.9.3 → C 节」。

**为什么需要它**：v1.9.2 审计发现，此前对外发布的四工况基线是用一份**外部测试脚本**跑出来的，
而该脚本写于成本模型扩展之前，调 `calcCostEstimate` 时少传三个参数——它算的是旧口径，
误差 3.41 元/kg，被写进三个文件对外发布。根因不是某个公式错，
而是**验证路径与产品路径不是同一条**。因此本自检的唯一设计约束是：
必须调用真实的 `recomputeAll()`、读真实的 `lastResults.summary`，不得重新实现任何计算管线。
